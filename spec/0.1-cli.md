# CLI contract 0.1

Normative behaviour for `session-contract` subcommands. Schema and verdict table remain in [spec 0.1](./0.1.md). Adapter input remains in [0.1-adapter.md](./0.1-adapter.md). Live Claude Code writer: [0.1-cc-hooks.md](./0.1-cc-hooks.md).

Exit 0 means “the checker finished and left an auditable claim”. It does **not** mean the session is acceptable. `accept` in `verdict.md` is the publication gate. CI that needs a quality gate MUST parse the claim (and `accept` if the workflow requires a published pack).

## 1. Exit codes

| Exit | When |
|---|---|
| **2** | The process cannot run the command: bad argv, pack path is not a directory, I/O error, or a **required input file** is missing. Required for `check`: `contract.md`, `evidence.ndjson`, `evidence.ndjson.sha256`. **`verdict.md` is not required** (exit 0 creates it). |
| **1** | The pack is **invalid**. No claim is written. Existing `verdict.md` is **not** deleted or modified (even if its `accept` points at an old chain). |
| **0** | Chain-valid pack; claim written. Axes may be `incomplete` / `overreach`; that is data, not a process failure. |

Invalid (exit 1) includes, in addition to spec §4.6 failures (broken `prev`/`hash`, sidecar file-bytes mismatch, `start.contract_sha256` ≠ on-disk `contract.md`, unparseable / incomplete contract YAML):

- `end` is followed by any further event
- more than one `end`
- a `kind` other than `start` \| `tool_call` \| `tool_result` \| `end`
- `start` missing or not the first event

A compliant 0.1 adapter cannot emit the first three of those (dsh `end` is constructed last; Claude Code `end` is only `SessionEnd` / `StopFailure` and nothing is appended after). Treating them as valid would mint a claim for a tampered or non-0.1 log.

## 2. `session-contract check <pack>`

Reads **only** the three required files inside `<pack>`. It MUST NOT require a ZIP, hook JSON, or any path outside the pack (adapter §4). Extra files in the directory are ignored.

On exit 0, stdout is exactly one line and nothing else:

```text
outcome=<x> compliance=<y> suspected_spin=<z> verdict=<abs-path>
```

Errors go to stderr. Do not dump the claim on stdout.

### 2.1 Claim fence (C1)

Identify the claim by **content**, not by “the first markdown fence”:

- A claim fence is a markdown fence whose body parses as YAML with `role: claim` **and** `session_contract: "0.1"`.
- Prose fences (including code samples in human notes **outside** the claim) are left untouched.
- Rewrite replaces **only** that claim fence.

If several fences match, the pack is invalid (exit 1, no write).

If a fence’s raw body contains those two keys but the YAML does not parse, treat it as the claim fence and **rebuild the whole fence**. Human `accept` / `note` on that block are lost. That is accepted: the claim is checker territory; evidence is the source of truth.

If `chain_tip` in a successfully parsed previous claim equals the new tip, preserve `accept` and `note`. If the tip changed, drop them.

Checker MUST NOT set `accept`.

0.1 spec §5.2 still says “exactly one fenced YAML block”; 0.1.1 SHOULD say “exactly one **claim** fence”. This CLI does the latter. Spec text is not changed in 0.1.

### 2.2 `reasons[]`

Each finding is one entry, in log-walk order, then unmatched-call warnings, then the single outcome code (`incomplete.goal` **or** `incomplete.truncated`, never both). `call_id` is present when the finding is about a tool pair.

`warning.unmatched_tool_call` is appended **after** the walk, in the order those `tool_call`s first appeared (`open` order). That is one of two exceptions to “emit at the moment the line is seen”; the other is the trailing outcome code. Dangling calls are known only at EOF; spec §6.2 also requires them to reset the redundant streak, which the checker does on a second pass over the dangling set.

`warning.*` entries go in the same array. They never set `compliance: overreach` by themselves.

`spin.redundant_streak`: **one reason per streak** (not per call). `call_id` is `gen_ai.tool.call.id` of the **first pair** in that streak. A streak is `redundant.n` or more consecutive paired calls matching spec §6.2.

## 3. `session-contract adapt dsh <zip-or-jsonl> --out <pack> [--contract <file>]`

Post-hoc only. Does not run `check`.

- Create `--out` if it does not exist.
- `contract.md` MUST be on disk in `--out` before `start` is written. If `--contract` is given and `--out/contract.md` is missing, copy `--contract` bytes into `--out/contract.md` (verbatim). If **both** exist, use the bytes already in `--out` (do not copy; a second copy can change CRLF and break `contract_sha256`). If neither exists, exit 1.
- If `--out/evidence.ndjson` already exists, exit 1 (refuse). 0.1 has no `--force`. Silent overwrite would destroy a chain.
- Writes `evidence.ndjson` and rewrites `evidence.ndjson.sha256` (final sidecar equals “refresh after every append”).
- Success: exit 0. stdout one line `out=<abs-pack>`.

Live Claude Code writing is not `adapt claude-code`. It is `cc-hook` / `cc-run` / `cc-init` (§4 and [0.1-cc-hooks.md](./0.1-cc-hooks.md)).

## 4. Claude Code subcommands

Exit codes in §1 apply to `check` and `adapt`. Hook processes use **D8**: never exit 2.

### 4.1 `session-contract cc-hook <Event>`

Invoked only by Claude Code. Requires env `SESSION_CONTRACT_PACK`. Reads one JSON object from stdin. Event name in argv MUST match `hook_event_name`.

| | |
|---|---|
| stdout | empty (never decision JSON) |
| exit 0 | recorded or skipped (omit / subagent / already `end`) |
| exit 1 | config/internal failure; stderr one line; **no** evidence line on fail-closed paths |
| exit 2 | forbidden |

See [0.1-cc-hooks.md](./0.1-cc-hooks.md) D4–D8.

### 4.2 `session-contract cc-run --contract <file> [--pack <dir>] [--] <claude args…>`

| | |
|---|---|
| stdout | empty |
| stderr | one line `pack=<abs>` then exec |
| exit 2 | bad argv, `--contract` missing on disk, cannot create `--pack` |
| exit 1 | `--pack/contract.md` missing and copy from `--contract` failed |
| else | `claude`’s exit code |

Default `--pack`: `./.session-contract/packs/<UTC YYYYMMDDTHHMMSSZ>-<4hex>`. Existing `contract.md` in the pack is never rewritten. Existing `evidence.ndjson` is appended to, not refused. Exports `SESSION_CONTRACT_PACK` then execs `claude`.

### 4.3 `session-contract cc-init [--print] [--write user|project]`

Default `--print`.

| | |
|---|---|
| stdout (`--print`) | JSON `{ "hooks": { … } }` only |
| `--write user` | merge into `~/.claude/settings.json` |
| `--write project` | merge into `./.claude/settings.json` |
| exit 0 | printed or merged |
| exit 2 | bad argv |
| exit 1 | `--write` target exists but is not object JSON |

Idempotent: do not duplicate a `cc-hook` entry already present for that event (match the shell `command` string). Replace a previous args-form session-contract entry. Do not strip other hooks. Do not rewrite other top-level keys.
