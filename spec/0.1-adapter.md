# Adapter input 0.1 (draft for review)

This document is **not** the checker. It says how a harness dump becomes `evidence.ndjson` under [spec 0.1](./0.1.md). The checker only reads a finished pack.

Two 0.1 adapters (two consumers, no runtime fork):

| Adapter | Source | When |
|---|---|---|
| `dsh` | `/export` ZIP or a raw `session.jsonl` | Post-hoc |
| `claude-code` | Hook stdin JSON (`PostToolUse`, `PostToolUseFailure`, `Stop`, …) | Append-only during the session; verdict still post-hoc |

Neither adapter is the verdict. Live hooks MUST NOT set `outcome: pass` from model text. Stop-hook false negatives are expected ([Claude Code #29881](https://github.com/anthropics/claude-code/issues/29881)).

## 1. Shared rules

1. Emit only §4 event kinds. Compute `prev` / `hash` after the payload object is complete.
2. `ts`: RFC 3339 UTC with `Z`. If the source has Unix epoch **milliseconds** (dsh `time`), convert with `new Date(ms).toISOString()`.
3. Parse tool arguments to JSON when possible. If parse fails, `arguments_sha256` is SHA-256 of `canonical(<raw string>)` (the string value, not a fake object).
4. `digest` is SHA-256 of the **result body UTF-8 bytes** defined per adapter below. Then `result_sha256` as in spec §4.2.
5. Relative write paths MUST be resolved against the session cwd **before** emit. If cwd is missing, leave `write_paths` empty (may yield `warning.unattested_write` for `fs.write`).
6. Unknown tool names: map to `exec`, `write_paths: []`, `network` omitted. Document the name in no evidence field (0.1 has no `unmapped` key). A later mapping file can override without breaking packs.
7. **Do not** put full arguments or full results on the evidence line.
8. Subagent logs: **out of 0.1**. dsh ZIP `subagents/` is ignored. Claude Code `agent_id` events are ignored (main session only).

## 2. dsh adapter

### 2.1 Input

Preferred: the ZIP from `GET /api/session.export` (Web `/export` or Session log download). Layout ([dsh-host-apiproxy](https://github.com/deepseek-ai/deepseek-harness)):

```text
session.jsonl          # or session.jsonl.zst — UTF-8 JSONL after decode
subagents/<id>/…       # ignore in 0.1
media/…                # ignore in 0.1
```

Also accept a bare `session.jsonl` / `.jsonl.zst` file.

The artifact is **verbatim durable bytes**, not a reconstructed view. First line is the session header (`type: "session"`), then event envelopes.

### 2.2 Header line (`type: "session"`)

Use:

- `id` → evidence `start.session_id`
- `cwd` → argument path resolution
- `createdAt` → `start.ts` if it is already an ISO string; if it is epoch ms, convert

Emit exactly one evidence `start`:

```json
{
  "kind": "start",
  "ts": "<from createdAt>",
  "contract_sha256": "<on-disk bytes of the pack's contract.md>",
  "harness": "dsh",
  "session_id": "<header.id>"
}
```

(`hash` / `prev` omitted in examples.)

If the header line is missing or not `type: "session"`, the adapter MUST fail (no pack).

### 2.3 Event envelope

Each following line:

```json
{
  "type": "<SessionEvent type>",
  "seq": 0,
  "time": 1710000000000,
  "data": {}
}
```

`time` is a safe integer (epoch ms). Ignore other envelope keys (`surfaceOp`, `sourceEventSeqs`, `ignorable`). Ignore packed chunk storage rows (`text-chunks`, etc.): they are not `tool/call` / `tool/result`.

Walk lines in file order (which is seq order).

### 2.4 `tool/call` → evidence `tool_call`

From `data`:

| dsh | evidence |
|---|---|
| `data.name` | `gen_ai.tool.name` |
| `data.callId` | `gen_ai.tool.call.id` |
| `data.arguments` (JSON **string**) | parse → `arguments_sha256` |
| `data.time` via envelope `time` | `ts` |

`gen_ai.operation.name` = `execute_tool`.

Capability, `write_paths`, `network`: §2.6–§2.7.

### 2.5 `tool/result` → evidence `tool_result`

Pair by `data.message.source.callId` (must equal the prior `tool/call` `callId`).

Result body for `digest`:

1. Take `data.message.content` (array). For each block with `type: "text"`, append `text` in order, joined with `""`.
2. If there is no text, use empty bytes.
3. Do **not** hash `meta` (presentation-only).

`isError`: `true` if `data.message.content[0].isError === true` **or** `data.error` is present.

Dangling `tool/call` (no result before EOF): leave unpaired; checker emits `warning.unmatched_tool_call`.

### 2.6 Capability map (dsh names, 0.1)

| `data.name` | capability | `write_paths` | `network` |
|---|---|---|---|
| `read`, `read_image` | `fs.read` | `[]` | omit |
| `write`, `edit` | `fs.write` | `[abs(file_path)]` | omit |
| `bash` | `exec` | `[]` | omit |
| `web_fetch` | `network` | `[]` | `true` |
| `grep`, `glob` | `fs.read` | `[]` | omit |
| `net_doctor` | `network` | `[]` | `true` |
| `job_output`, `job_list`, `job_kill` | `exec` | `[]` | omit |
| anything else | `exec` | `[]` | omit |

`file_path` comes from parsed `arguments`. Resolve with header `cwd` if relative.

**Known hole:** `bash` that runs `curl` is still `exec` without `network: true`. 0.1 does not parse shell. Overreach for `capabilities.network: deny` will miss in-shell HTTP. That is accepted for 0.1.

### 2.7 Evidence `end`

If the log contains at least one `turn/end` **and** every `tool/call` has a `tool/result`, emit:

```json
{
  "kind": "end",
  "ts": "<time of last turn/end>",
  "stop_reason": "user"
}
```

`stop_reason` in 0.1:

- last event is `turn/end` and no dangling calls → `user` if a later `user/message` is not needed; use `model` when the last `turn/end` exists and the last `user/message` is not after it → **simpler 0.1:** always `model` when `turn/end` exists and the session was not aborted.
- `abort` if a closer/repair result with `TOOL_OUTCOME_UNKNOWN` / interrupted markers appears
- otherwise omit `end` (truncated pack)

0.1 MUST prefer omitting `end` over guessing. If unsure, do not emit `end` (`incomplete.truncated`).

**0.1 simplification (normative):** emit `end` with `stop_reason: "model"` iff there is a `turn/end` whose `seq` is greater than every `tool/call` that lacks a `tool/result`. Otherwise no `end`.

## 3. Claude Code adapter

Hooks receive JSON on stdin ([Hooks](https://code.claude.com/docs/en/hooks)). 0.1 uses them as an **append-only evidence writer**, not as a live verdict.

### 3.1 Files

The hook implementation SHOULD write to a pack directory the user names (env `SESSION_CONTRACT_PACK`). Create `evidence.ndjson` on first event. On `Stop` / `StopFailure`, emit `end` then the sidecar hashes. Checker runs afterwards on that directory plus `contract.md`.

### 3.2 Common fields

| hook | evidence |
|---|---|
| `session_id` | `start.session_id` |
| `cwd` | path resolution |
| `hook_event_name` | routing |
| `tool_name` | `gen_ai.tool.name` |
| `tool_use_id` | `gen_ai.tool.call.id` |
| `tool_input` | object → `arguments_sha256` (already JSON, not a string) |

`harness`: `"claude-code"`.

Ignore events with `agent_id` set (subagent).

### 3.3 Which hook events

| Hook | Evidence |
|---|---|
| First event in an empty log | `start` (then the tool pair if any) |
| `PreToolUse` | `tool_call` only (no result yet) |
| `PostToolUse` | if `tool_call` for this id already exists, emit `tool_result` with `isError: false`; else emit `tool_call` then `tool_result` |
| `PostToolUseFailure` | same pairing; `isError: true`; digest body = UTF-8 of `error` string |
| `PermissionDenied` | `tool_call` + `tool_result` with `isError: true`, digest = UTF-8 of `reason` (call was denied; still evidence) |
| `Stop` | `end`, `stop_reason: "user"` if `stop_hook_active` is not used to infer crash; 0.1: `stop_reason: "model"` |
| `StopFailure` | `end`, `stop_reason: "error"` |

Do **not** use `last_assistant_message` for `outcome`.

`PostToolUse` alone is not enough: failures and denials would vanish. 0.1 hook config MUST register PostToolUse **and** PostToolUseFailure **and** PermissionDenied **and** Stop.

### 3.4 Result body (`digest`)

- `PostToolUse`: UTF-8 of `canonical(tool_response)` if `tool_response` is an object; else UTF-8 of `String(tool_response)`.
- `PostToolUseFailure`: UTF-8 of `error` (empty if missing).
- Do not use `updatedToolOutput` (that is hook output to the model, after the fact).

### 3.5 Capability map (Claude Code names, 0.1)

| `tool_name` | capability | `write_paths` | `network` |
|---|---|---|---|
| `Read`, `Glob`, `Grep` | `fs.read` | `[]` | omit |
| `Write`, `Edit`, `NotebookEdit` | `fs.write` | `[abs(file_path)]` | omit |
| `Bash`, `PowerShell` | `exec` | `[]` | omit |
| `WebFetch`, `WebSearch` | `network` | `[]` | `true` |
| `mcp__*` | `network` | `[]` | `true` |
| anything else | `exec` | `[]` | omit |

`Write`/`Edit` `file_path` is already absolute in hook JSON (native separators). Normalize `\\` → `/` before prefix checks (spec §3.2).

Same bash/curl hole as dsh.

### 3.6 Parallel tools

`PostToolUse` may fire concurrently. The writer MUST serialize appends (file lock or a queue) so ndjson lines and the hash chain stay ordered. `PostToolBatch` is **not** used in 0.1 (duplicate of per-tool events; different `tool_response` shape).

## 4. Checker input

After an adapter finishes:

```text
<pack>/contract.md          # user-authored
<pack>/evidence.ndjson      # adapter
<pack>/evidence.ndjson.sha256
```

The checker verifies hashes, walks the chain, writes `verdict.md` claim. It MUST NOT require the original ZIP or hook JSON.

CLI shape (informative, not implemented this round):

```text
session-contract adapt dsh ./export.zip --contract contract.md --out ./pack
session-contract check ./pack
```
