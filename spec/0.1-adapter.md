# Adapter input 0.1 (draft for review)

This document is **not** the checker. It says how a harness dump becomes `evidence.ndjson` under [spec 0.1](./0.1.md). The checker only reads a finished pack.

Two 0.1 adapters (two consumers, no runtime fork):

| Adapter | Source | When |
|---|---|---|
| `dsh` | `/export` ZIP or a raw `session.jsonl` / `session.jsonl.zstd` | Post-hoc |
| `claude-code` | Hook stdin JSON | Append-only during the session; verdict still post-hoc |

Neither adapter is the verdict. Live hooks MUST NOT set `outcome: pass` from model text. Stop-hook false negatives are expected ([Claude Code #29881](https://github.com/anthropics/claude-code/issues/29881)).

Spec §3.3 constrains **classification of emitted events**. It does **not** require a complete transcript. Omitting a harness tool is compliant. The omit set MUST be listed in this document so checker silence is not read as “that tool never ran”.

## 1. Shared rules

1. Emit only §4 event kinds. Compute `prev` / `hash` after the payload object is complete. Event JSON values MUST be string / boolean / integer / array / object only — **no float, no `null`** (spec §4.1).
2. `ts`: RFC 3339 UTC with `Z`.
   - If the source has Unix epoch **milliseconds**, convert with `new Date(ms).toISOString()`.
   - If the source has **no timestamp** (Claude Code hooks), use the **wall clock at receive**.
3. Parse tool arguments to JSON when possible. If parse fails, `arguments_sha256` is SHA-256 of `canonical(<raw string>)` (the string value, not a fake object).
4. `digest` is SHA-256 of the adapter’s **recorded result body** (UTF-8), then `result_sha256` as in spec §4.2. Each adapter defines that body below.
5. Relative write paths MUST be resolved against the session cwd **before** emit. If cwd is missing, leave `write_paths` empty (may yield `warning.unattested_write` for `fs.write`).
6. Unknown tool names (not in the map, not in the omit set): map to `exec`, `write_paths: []`, `network` omitted. The fallback is only for **truly unknown** tools. Documented omit names MUST NOT go through this fallback (`exec: deny` would otherwise false-positive overreach).
7. **Do not** put full arguments or full results on the evidence line.
8. Subagent logs: **out of 0.1**. dsh ZIP `subagents/` is ignored. Claude Code events with `agent_id` set are ignored (main session only).
9. **Do not** use `last_assistant_message` (or any model text) for `outcome`.

### 1.1 Pack directory: sign first, then work

`start.contract_sha256` is SHA-256 of **on-disk bytes of `contract.md` at the moment the first evidence event is written**. A contract written after that is a mismatch reject (spec §2.1 / §4.6).

Therefore:

- `contract.md` MUST already sit in the pack directory **before** the adapter emits `start`.
- Post-hoc `dsh`: the CLI takes `--contract` (or the file already in `--out`) and copies/uses those bytes; it does not invent a contract after walking the log.
- Live `claude-code`: the user (or a bootstrap script) places `contract.md` in `SESSION_CONTRACT_PACK` before the session. If the file is missing at `start`, the adapter MUST fail closed (no evidence line).

This is the contract’s semantics: sign, then work.

### 1.2 Sidecar after every append

`evidence.ndjson.sha256` is two ASCII lines (spec §4.4):

```text
<sha256-of-file-bytes>  evidence.ndjson
chain_tip  <hex>
```

Rewrite **both lines after every appended event**, not only at session end. A crash with no `end` still has a sidecar; otherwise the checker rejects the pack as invalid under §4.6 instead of `incomplete.truncated`.

`chain_tip` is the `hash` of the current last line.

## 2. dsh adapter

### 2.1 Input

Preferred: the ZIP from `GET /api/session.export` (Web `/export` or Session log download). Layout ([dsh-host-apiproxy](https://github.com/deepseek-ai/deepseek-harness)):

```text
session.jsonl            # plaintext JSONL, or
session.jsonl.zstd       # zstd frame (logSuffix); ZIP stores those bytes as-is
subagents/<id>/…         # ignore in 0.1
media/…                  # ignore in 0.1
```

Also accept a bare `session.jsonl` / `session.jsonl.zstd` file. The suffix is **`.jsonl.zstd`**, not `.zst`.

Detect compression by magic bytes `28 B5 2F FD` at offset 0; if present, zstd-decompress, then parse UTF-8 JSONL. Do not trust the filename alone (a `.jsonl` name can still be a zstd frame inside a ZIP).

The artifact is **verbatim durable bytes**, not a reconstructed view. First line is the session header (`type: "session"`), then event envelopes.

### 2.2 Header line (`type: "session"`)

Use:

- `id` → evidence `start.session_id`
- `cwd` → argument path resolution
- `createdAt` → `start.ts` (this field is **always** epoch milliseconds; there is no ISO branch)

Emit exactly one evidence `start`:

```json
{
  "kind": "start",
  "ts": "<from createdAt>",
  "contract_sha256": "<on-disk bytes of the pack's contract.md>",
  "harness": "dsh",
  "session_id": "<header.id>"
}
```

(`hash` / `prev` omitted in examples.)

If the header line is missing or not `type: "session"`, the adapter MUST fail (no pack).

### 2.3 Event envelope

Each following line:

```json
{
  "type": "<SessionEvent type>",
  "seq": 0,
  "time": 1710000000000,
  "data": {}
}
```

`time` is a safe integer (epoch ms) on the **envelope**, not inside `data`. Event `ts` comes from that field.

Ignore other envelope keys (`surfaceOp`, `sourceEventSeqs`, `ignorable`). Ignore packed chunk storage rows (`text-chunks`, etc.): they are not `tool/call` / `tool/result`.

Walk lines in file order (which is seq order).

### 2.4 `tool/call` → evidence `tool_call`

From `data` plus the envelope:

| source | evidence |
|---|---|
| `data.name` | `gen_ai.tool.name` |
| `data.callId` | `gen_ai.tool.call.id` |
| `data.arguments` (JSON **string**) | parse → `arguments_sha256` |
| envelope `time` | `ts` |

`gen_ai.operation.name` = `execute_tool`.

If `data.name` is in the omit set (§2.6), skip this call **and** its later `tool/result` (same `callId`).

Capability, `write_paths`, `network`: §2.6.

### 2.5 `tool/result` → evidence `tool_result`

Pair by `data.message.source.callId` (must equal the prior `tool/call` `callId`).

**Recorded result body (lossless):**

```text
digest = SHA-256( UTF-8 of canonical(data.message.content) )
```

`canonical` is spec §4.4. `content` is the harness array (text blocks, image blocks, …). Two `read_image` calls with different pictures therefore differ; two identical pictures collide only if the harness content is identical.

If `content` is missing, hash `canonical([])`.

Do **not** hash `meta` (presentation-only).

`isError`: `true` if `data.message.content[0].isError === true` **or** `data.error` is present.

Dangling `tool/call` (no result before EOF): leave unpaired; checker emits `warning.unmatched_tool_call`.

### 2.6 Capability map and omit set (dsh names, 0.1)

**Emit** (classified):

| `data.name` | capability | `write_paths` | `network` |
|---|---|---|---|
| `read`, `read_image` | `fs.read` | `[]` | omit |
| `write`, `edit` | `fs.write` | `[abs(file_path)]` | omit |
| `bash` | `exec` | `[]` | omit |
| `grep`, `glob` | `fs.read` | `[]` | omit |
| `skill` | `fs.read` | `[]` | omit |
| `web_search` | `network` | `[]` | `true` |
| `web_fetch` | `network` | `[]` | `true` |
| `net_doctor` | `network` | `[]` | `true` |
| anything else **not listed in omit** | `exec` | `[]` | omit |

`file_path` comes from parsed `arguments`. Resolve with header `cwd` if relative.

`web_search` is the registered network-search tool (evidence name `tool:web_search`). `web_fetch` is optionally exposed in the same pack; both are `network: true` when present.

**Omit** (no `tool_call` / `tool_result`; internal / UI / job-control / delegation — not evidence of §3.3 capabilities):

| `data.name` | Why |
|---|---|
| `todo_write` | UI / plan list |
| `create_goal` | UI / goal board |
| `ask_user_question` | UI prompt |
| `job_output`, `job_list`, `job_kill` | job control, not a user-capability exec |
| `ralph` | loop / orchestration |
| names matching `subagent*` | delegation; subagent ZIP is out of 0.1 |
| names matching `workflow*` | orchestration |

Omitted tools MUST NOT use the `exec` fallback. Silence in the evidence log for these names means “adapter dropped them”, not “they did not run”. A name in the omit table that never appears in the source is a no-op; that is safe (missing a name is not: it falls through to `exec` and can false-positive overreach).

**Known hole:** `bash` that runs `curl` is still `exec` without `network: true`. 0.1 does not parse shell. Overreach for `capabilities.network: deny` will miss in-shell HTTP. That is accepted for 0.1.

### 2.7 Evidence `end`

`turn/end` is a **turn** close, not a session close. The post-hoc adapter emits **at most one** evidence `end`, derived from the **last** `turn/end` in the file, and only if that event is terminal:

- There is at least one `turn/end`.
- After skipping omitted-tool envelopes (`tool/call` / `tool/result` whose name is in §2.6 omit) and packed-chunk / `ignorable` rows, that `turn/end` is the **last remaining line** in the log (so a late `tool/result` after the turn closed still blocks `end`).
- The last `turn/end` `data.reason.kind` is **not** `blocked`.

`end.ts` is that last `turn/end` envelope’s `time` (epoch ms → ISO).

Otherwise omit `end` (`incomplete.truncated`). Prefer omitting `end` over guessing.

Map `data.reason` of that last `turn/end` (`TurnEndReasonMap` in `@deepseek-ai/dsh-session`):

| `reason.kind` (and cancel cause) | `stop_reason` |
|---|---|
| `completed` | `model` |
| `max-tokens` | `model` |
| `aborted` and `reason.reason.kind === "user"` | `user` |
| `error` | `error` |
| `aborted` with cause `parent` / `hook` / `disposed` / `legacy` | `abort` |
| `interrupted` | `abort` |
| `blocked` | **do not emit `end`** |

Normal UI stop is `aborted` + cause `user`, not `completed`.

A crash with no later `turn/end` → no `end` → `incomplete.truncated`. That is the M3 path.

## 3. Claude Code adapter

Hooks receive JSON on stdin ([Hooks](https://code.claude.com/docs/en/hooks)). 0.1 uses them as an **append-only evidence writer**, not as a live verdict.

**Stop is not session end.** `Stop` fires at the end of **each model response**. Emitting evidence `end` on the first `Stop` yields a chain with events after `end` and a stale sidecar. 0.1 does not do that.

### 3.1 Files

Pack directory = env `SESSION_CONTRACT_PACK`. `contract.md` MUST already be there (§1.1). Create `evidence.ndjson` on first emit. Rewrite the sidecar after every append (§1.2).

Checker runs afterwards on that directory.

### 3.2 Common fields

| hook | evidence |
|---|---|
| `session_id` | `start.session_id` |
| `cwd` | path resolution |
| `hook_event_name` | routing |
| `tool_name` | `gen_ai.tool.name` |
| `tool_use_id` | `gen_ai.tool.call.id` |
| `tool_input` | object → `arguments_sha256` (already JSON, not a string) |

`harness`: `"claude-code"`.

`ts`: wall clock at receive (hooks have no timestamp).

Ignore events with `agent_id` set (subagent).

If `tool_name` is in the omit set (§3.5), skip the event.

### 3.3 Which hook events

| Hook | Evidence |
|---|---|
| `SessionStart` (recommended) | `start`. Copy `session_id`. Optional extra keys `source` / `session_title` MAY be copied onto `start`; a 0.1 checker ignores them. Cost is zero versus synthesizing `start` from the first tool event on an empty log. |
| First tool event on an empty log, if `SessionStart` was not registered | synthesize `start`, then the tool event |
| `PreToolUse` | `tool_call` only |
| `PostToolUse` | if `tool_call` for this `tool_use_id` already exists, emit `tool_result` with `isError: false`; else emit `tool_call` then `tool_result` |
| `PostToolUseFailure` | same pairing; `isError: true`; recorded body = UTF-8 of `error` (empty if missing) |
| `PermissionDenied` | same pairing; `isError: true`; recorded body = UTF-8 of `reason`. Makes a denied attempt visible. |
| `Stop` | **not** `end`. Turn boundary only. `stop_hook_active` is internal bookkeeping (do not copy onto evidence). |
| `SessionEnd` | `end`, `stop_reason: "user"`. Input `reason` is `clear \| resume \| logout \| prompt_input_exit \| other` — all user-side. |
| `StopFailure` | `end`, `stop_reason: "error"` (rate_limit / overloaded / auth / …). The session will not append more tools after this. |

A crash with no `SessionEnd` → no `end` → `incomplete.truncated` (M3). Correct.

0.1 hook config MUST register: `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, `SessionEnd`, `StopFailure`. SHOULD register `SessionStart`. MAY register `Stop` only for local turn accounting.

**Accepted noise:** `PreToolUse` can fire for a call that is then abandoned (no `PostToolUse` / `PostToolUseFailure` / `PermissionDenied`). That leaves a dangling `tool_call` → `warning.unmatched_tool_call`. 0.1 accepts that in exchange for seeing denied attempts.

Do **not** use `PostToolBatch` (per-tool events already cover the same calls; `tool_response` shape differs).

Do **not** use `last_assistant_message` for `outcome`.

### 3.4 Result body (`digest`)

- `PostToolUse`: UTF-8 of `canonical(tool_response)` if `tool_response` is an object; else UTF-8 of `String(tool_response)`.
- `PostToolUseFailure`: UTF-8 of `error` (empty if missing).
- `PermissionDenied`: UTF-8 of `reason` (empty if missing).
- Do not use `updatedToolOutput` (hook output to the model, after the fact).

### 3.5 Capability map and omit set (Claude Code names, 0.1)

**Emit:**

| `tool_name` | capability | `write_paths` | `network` |
|---|---|---|---|
| `Read`, `Glob`, `Grep` | `fs.read` | `[]` | omit |
| `Skill` | `fs.read` | `[]` | omit |
| `Write`, `Edit`, `NotebookEdit` | `fs.write` | `[abs(file_path)]` | omit |
| `Bash`, `PowerShell` | `exec` | `[]` | omit |
| `WebFetch`, `WebSearch` | `network` | `[]` | `true` |
| `mcp__*` | `network` | `[]` | `true` |
| anything else **not listed in omit** | `exec` | `[]` | omit |

`Write` / `Edit` `file_path` is already absolute in hook JSON (native separators). Normalize `\\` → `/` before prefix checks (spec §3.2).

**Cost of `mcp__*` → `network`:** conservative. A **local stdio MCP** is not network but still tagged `network: true`. Therefore `capabilities.network: deny` bans **all** MCP, including stdio. That is accepted for 0.1; document it on the contract if the session uses local MCP.

**Omit** (same rationale as §2.6):

| `tool_name` | Why |
|---|---|
| `Task` | delegation; subagent `agent_id` events are already ignored |
| `TodoWrite` | UI / plan list |
| `AskUserQuestion` | UI prompt |
| `EnterPlanMode`, `ExitPlanMode` | mode / UI |
| `TaskOutput` | job-control analogue |
| `KillShell`, `BashOutput` | job / shell control (same reason as dsh `job_kill`) |

A name in the omit table that never appears in the source is a no-op; that is safe (missing a name is not: it falls through to `exec` and can false-positive overreach).

Same bash/curl hole as dsh.

### 3.6 Parallel tools

`PostToolUse` may fire concurrently. The writer MUST serialize appends (file lock or a queue) so ndjson lines, the hash chain, and the sidecar stay ordered.

## 4. Checker input

After an adapter finishes (or after a crash with a current sidecar):

```text
<pack>/contract.md          # already present before start
<pack>/evidence.ndjson      # adapter
<pack>/evidence.ndjson.sha256
```

The checker verifies hashes, walks the chain, writes `verdict.md` claim. It MUST NOT require the original ZIP or hook JSON.

CLI shape (informative, not implemented this round):

```text
session-contract adapt dsh ./export.zip --contract contract.md --out ./pack
session-contract check ./pack
```

## 5. Out of scope (this document)

- Implementing the CLI
- Parsing `bash` / `Bash` command strings for network or write paths
- Subagent ZIP folders / `agent_id`
- `goal_check`
- Using Stop `last_assistant_message` as pass
- Treating omitted tools as checker findings

## 6. Locked decisions (review)

- `PreToolUse` + `PermissionDenied`: denied attempts are visible evidence. Dangling `tool_call` noise is accepted.
- `PostToolUse` / `PostToolUseFailure.error` / `PermissionDenied.reason`: field names as in current hooks docs; use as specified.
- Parallel hook writes MUST be serialized. `PostToolBatch` is unused.
- `mcp__*` → `network` stays conservative, with the stdio cost in §3.5.
- `bash` / `Bash` / curl-in-shell is not `network`. Subagent logs ignored. `last_assistant_message` never feeds the verdict.
- Claude Code `end` only from `SessionEnd` / `StopFailure`. `Stop` is a turn boundary.
- Sidecar is incremental. `contract.md` precedes `start`.
